Executive summary

The former one-GiB bounded-session admission ceiling was a fixed safety threshold, not a measured parser or sidecar limitation. The ceiling is now 2 GiB plus 1 MiB of bounded fork-header headroom, and automatic routing keeps ordinary transcripts eager while admitting large transcripts through bounded session memory.

Findings and interpretation

Raw first-open cost

The raw cold first-open operation performs security/semantic validation and sidecar construction when no authenticated artifact exists. It is not an exact authenticated reopen, a transcript-ahead recovery, or a fork copy.

Exact reopen and transcript-ahead evidence

Fresh-process authenticated reopen and transcript-ahead recovery are represented as separate operation classes. Their setup first-open evidence is retained under preparation rather than folded into reopen latency.

Memory behavior

Maximum operation RSS growth was 96.7 MiB. Maximum post-close growth was 98.7 MiB. Maximum whole-process RSS was 441.5 MiB, which includes fixture generation and allocator high-water residency and is not equivalent to reachable session state.

Lookup behavior

Maximum cold p95 was 1.96 ms and maximum warm p95 was 0.07 ms. Warm lookups added 0 range reads across the represented runs.

Unavailable phase telemetry: phase/counter fields remain null or absent when the runtime does not expose them; the report does not infer semantic, write, GC, or fsync measurements from aggregate open time.

Methodology

  • Synthetic JSONL only; no private or provider transcript data.
  • Each scenario/size point runs in a fresh Bun subprocess with --smol --expose-gc.
  • Operation baselines are captured after fixture generation; raw cold first-open is not labeled as resume.
  • Every transcript has an active compaction boundary and cold history stored as 256 KiB payload records.
  • Multiple-transcript and subagent totals are partitioned across four and five files respectively, then held open concurrently.
  • Cold lookup reads one retired entry per open session; the same IDs are immediately repeated for the warm-cache invariant.
  • Sidecar accounted bytes, process RSS, heap/external memory, CPU usage, throughput, close latency, context count, I/O counters, operation class, and optional phase evidence are retained in JSON evidence.

Limitations

  • One run per dense matrix point; this is scaling evidence, not variance characterization.
  • Synthetic repeated text does not model every production distribution, image/blob mix, branching topology, or filesystem fragmentation state.
  • Process RSS includes allocator behavior and native runtime state. It must not be read as a direct leak measurement.
  • Subagent sessions are represented as parent-linked session files and role-tagged records; model/provider execution is intentionally excluded.
  • Managed retained-authority sessions remain on their separate eager compatibility path.
