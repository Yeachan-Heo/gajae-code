## Status vocabulary

| Status | Meaning |
|---|---|
| `candidate` | Listed, not started. |
| `blocked` | Implementation or dependency is present, but a documented decision or parity gap blocks adoption. |
| `in-progress` | Port is integrated on the branch; stays in-progress until PR and rehearsal run URLs are recorded. |
| `adopted` | Merged with parity, benchmark, and rehearsal evidence; replaced TS deleted with no fallback. |
| `rejected` | Not adopted; `reason` is mandatory. |
| `keep-local` | gjc-only Rust that a re-sync must not overwrite; guarded by named tests. |

## Shared gate tooling

### Differential harness

`packages/natives/test/differential/` provides a shared differential runner. `defineDifferential` binds a module name, stable case IDs and inputs, an optional live reference, a native implementation, optional semantic-only normalization, and a comparator. Record with `bun run diffcheck <module> --record` (record mode requires a live reference); verify with `bun run diffcheck <module>`. Goldens are JSONL records keyed by case ID and a SHA-256 hash of the canonical input. Verification reports `total`, `identical`, `accepted`, `unlisted`, and `stale`. Normalization may remove only explicitly declared non-semantic fields. Divergences belong in `divergences/<module>.json` with `caseId`, `reason`, `upstreamRationale`, `changelog`, and `testsUpdated`.

### A/B and RSS gates

`bun scripts/native-bench-ab.ts --suite edit-hotspots --base <base-sha> --json` runs the suite on the base worktree and current head on the same host, interleaved in paired blocks. Adapters emit `{schema:"gjc.native-bench-ab/1",suite,cases:[{id,status:"measured"|"skipped"|"error",samples:number[]}]}` when run with `--json --strict`. Default latency collection uses 15 paired blocks × 200 measured iterations after warmup. A/A calibration is same-commit mode: `bun scripts/native-bench-ab.ts --suite edit-hotspots --base HEAD --calibrate --json`; the RSS suite uses `--suite rss` and measures S1–S5,S7. Bootstrap resamples paired blocks of per-block p50 and p95 timings. PASS requires the upper 95% paired-block bootstrap CI for head/base p50 ≤ 1.03 and p95 ≤ 1.10. FAIL applies if the lower bound exceeds either threshold; otherwise the runner doubles blocks 15→30→60 and a still-inconclusive outcome fails. Skips, errors, missing cases, or empty samples fail.

For RSS, build the compiled binary on each side with `bun --cwd=packages/coding-agent run build`. For each side and each capture, run from that worktree root exactly: `bun scripts/verify-rss-checkpoints.ts --all --json > $AB/rss-<side>-<i>.json`. Compare `scenarios[id].rssBytes.stableTree.median` for measured S1,S2,S3,S4,S5,S7 with a paired bootstrap 95% CI; PASS requires upper bound ≤1.05 for every scenario. INCONCLUSIVE triggers K=10 once, then fails. A non-measured selected scenario fails. The legacy envelope also applies: base runs `bun scripts/verify-rss-checkpoints.ts --all --write-baseline --json`, then copy `.gjc/rss-checkpoints/<base-sha>.json` to `$AB/rss-base.json`; head runs `bun scripts/verify-rss-checkpoints.ts --all --compare --baseline $AB/rss-base.json --allow-baseline-drift --json` and must show zero regressions. Without `--allow-baseline-drift`, `BaselineIdentityMismatch` is an ERROR. The W5b idle rule is separately checked with `bun scripts/verify-module-trace.ts --scenario help,version,idle --milestone W5b`.
