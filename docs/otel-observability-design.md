# OpenTelemetry-compatible observability design (#2565)

Status: **design-phase, owner-triggered** — this document is the design deliverable requested by
[#2565](https://github.com/Yeachan-Heo/gajae-code/issues/2565). It does not change runtime
behavior. Product-source implementation of any stage below requires a separate, explicitly scoped
PR and stays out of bounds until the owner admits a concrete slice.

## 1. Problem framing and current-tree baseline

The coding-agent surface already has three independent observability surfaces that do not share a
correlation contract:

| Surface | Location | Correlation | Export |
| --- | --- | --- | --- |
| Agent-loop GenAI spans | `packages/agent/src/telemetry.ts` | `gen_ai.conversation.id` = session id; parent/child via active OTEL context | Opt-in — no-op unless an OTEL SDK is registered by the host (`AgentTelemetryConfig`) |
| Token-usage JSONL logs | `packages/coding-agent/src/task/*` (`persistTaskTokenLog`) | subagent id, turn number, session dir | Local file only, always on |
| Fatal crash capture | `packages/utils/src/postmortem.ts`, `crash-journal.ts`, `crash-fingerprint.ts` | crash fingerprint, record id, PID | Local rotation-immune log + append-only journal, always on |

The coding-agent CLI entry point (`packages/coding-agent/src/main.ts`) deliberately defaults spans
off (`{ spans: false }`) unless an SDK embedder supplies its own telemetry config
(`packages/coding-agent/src/sdk/session.ts`). There is no OTEL SDK/exporter dependency, no
CLI/config surface to turn on export, and no shared identifier between a `chat`/`execute_tool` span
and a postmortem crash record for the same process.

This document defines the contract that closes that gap. It does not implement it.

## 2. Canonical trace hierarchy

```
session (gjc.session.id, stable across process restarts of the same session)
└── run (gjc.run.id, one per top-level agentLoop invocation — CLI turn, SDK turn, harness turn)
    └── invoke_agent {agent.name}         [existing: gen_ai span]
        ├── chat {model}                  [existing: gen_ai span, one per LLM call]
        ├── execute_tool {tool.name}      [existing: gen_ai span, one per tool call]
        │   └── child_process {argv[0]}   [new: bash/spawn-backed tools]
        └── handoff / delegated task
            └── invoke_agent {child.agent.name}   [new: child session/run correlation]
                └── ... (recurses)
```

Identifiers:

- `gjc.session.id` — existing `SessionManager` session id. Stable for the life of a session,
  including across fork/resume; already threaded through `sessionOptions.telemetry` today.
- `gjc.run.id` — new. One per `agentLoop` invocation (a single user turn or subagent turn). Minted
  by the host (coding-agent), not by `packages/agent`, since only the host knows turn boundaries
  across compaction/retry. Propagated into `AgentTelemetryConfig` alongside the existing
  `conversationId`.
- OTEL `trace_id` / `span_id` — standard W3C trace context, generated by the registered
  `TracerProvider`. Cross-process propagation (parent CLI → spawned child agent process, e.g.
  `task` tool with `isolated: true`, or tmux/team child sessions) uses the standard `traceparent`
  environment variable / header, set by the parent before spawn and read by the child's telemetry
  bootstrap before its first span. This is the only new cross-process mechanism; in-process
  delegation already nests correctly via OTEL's active-context propagation
  (`packages/coding-agent/src/task/executor.ts:1594-1646`).
- `gjc.crash.fingerprint` / `gjc.crash.record_id` — existing postmortem identifiers
  (`packages/utils/src/crash-fingerprint.ts`, `crash-journal.ts`). The crash contract (§5) adds
  `gjc.session.id`, `gjc.run.id`, and the active `trace_id`/`span_id` (when available) as new,
  best-effort fields on the crash record and journal event — never as a requirement, since a crash
  before telemetry initializes must still produce a record.

New span kinds beyond the four already emitted by `packages/agent`:

- `child_process` — wraps a subprocess spawned by a tool (bash, git, lsp, natives shell). Attributes:
  argv[0] (binary name only, never full command line by default), exit code, signal, duration.
  Parented under the owning `execute_tool` span.
- `workflow_gate` — wraps a plan-approval / execution-approval gate transition (ralplan/deep-interview
  pending-approval → approved, team coordination gates). Attributes: gate kind, from/to state,
  actor (owner vs. automated).

## 3. Attribute classification

Every attribute is classified into exactly one bucket. Bucket membership is enforced at the
attribute-resolution boundary (the equivalent of today's `resolveDynamicAttributes` /
`applyContentCaptureForRequest` gates in `packages/agent/src/telemetry.ts`), not left to caller
discipline.

| Bucket | Rule | Examples |
| --- | --- | --- |
| **Always safe** | Structural metadata with no content; safe in any exporter, local or remote. | `gjc.session.id`, `gjc.run.id`, `gen_ai.operation.name`, `gen_ai.request.model`, `gen_ai.usage.*`, tool name, exit code, duration, span status, `error.type` |
| **Local-only** | Useful for local debugging; never leaves the process's local exporter (console/JSON file). Stripped by any remote/OTLP exporter path before send. | full stack traces, absolute filesystem paths, argv beyond argv[0], tool call arguments/results when `content_capture=summary` |
| **Explicitly opt-in redactable** | Governed by the existing `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` contract (`packages/agent/src/telemetry.ts`). Off by default; `summary` bounds size/depth; `full` requires the existing explicit warning path. | `gen_ai.input.messages`, `gen_ai.output.messages`, `gen_ai.system_instructions`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result` |
| **Forbidden** | Never attached to any span or crash record, in any mode. Enforced by omission from every attribute builder, not by redaction. | raw credentials/API keys, `.env` contents, full environment variable dump, repository file contents outside an explicit opt-in content-capture field, raw HTTP request bodies (already excluded — see `postmortem.ts` doc comment on `capturePayload`) |

This mirrors and extends the pattern already established by `postmortem.ts`'s
`CRASH_CONTEXT_FIELDS` allowlist and `redactCrashSecrets`, and by `telemetry.ts`'s content-capture
gate — the new work is applying the same allowlist-first discipline to the run/session/child-process
layer that today only exists for the GenAI chat layer.

Bounds (extending the existing `MAX_TELEMETRY_*` constants in `telemetry.ts`):

- Every string attribute ≤ 4 KiB (matches `CRASH_CONTEXT_FIELD_MAX_BYTES`).
- Every span ≤ 64 attributes.
- Every crash record ≤ `CRASH_RECORD_MAX_BYTES` (64 KiB) — unchanged, new correlation fields are a
  handful of short strings and fit comfortably inside the existing budget.

## 4. Local and OTLP export contract

Configuration surface (new `packages/coding-agent` settings key, e.g. `telemetry.export`):

```
telemetry.export.mode: "off" | "local" | "otlp"   // default: "off"
telemetry.export.local.path: string                 // default: <session dir>/telemetry/
telemetry.export.otlp.endpoint: string               // required when mode="otlp"
telemetry.export.otlp.headers: Record<string,string> // optional, e.g. auth
telemetry.export.sampling.ratio: number               // default: 1.0 for local, 0.1 for otlp
telemetry.export.contentCapture: "none"|"summary"|"full" // default: "none", forwards to OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT
```

- **`off` (default)**: identical to today's behavior — `AgentTelemetryConfig` unset or `spans: false`,
  zero tracer lookups, zero dependency on an OTEL SDK being registered.
- **`local`**: registers a local `TracerProvider` (already a devDependency via
  `@opentelemetry/sdk-trace-base`, promoted to a runtime dependency for coding-agent) writing
  bounded, redacted spans as JSON lines under the session directory. No network calls. This is the
  safe default for anyone who wants traces without an export destination.
  The unhandled-error capture in `postmortem.ts` stays the source of truth for crash records
  regardless of this setting — telemetry export never gates crash persistence.
- **`otlp`**: adds an `@opentelemetry/exporter-trace-otlp-http` (or grpc) span processor pointed at
  `telemetry.export.otlp.endpoint`. Requires an explicit endpoint; there is no default remote
  destination. Sampling defaults to 10% to bound both privacy exposure and network overhead;
  operators can set `sampling.ratio: 1.0` explicitly.

Failure isolation (hard requirement, testable):

- Exporter construction, span export, and flush all run through a bounded try/catch that never
  rethrows into the agent loop — mirrors the existing `safeOnSpanStart`/`safeOnSpanEnd` pattern in
  `telemetry.ts`, extended to the new exporter registration path.
- Flush on process exit is bounded by the existing `DEFAULT_CLEANUP_DEADLINE_MS` (5s) cleanup
  deadline in `postmortem.ts` — the exporter registers a `postmortem.register()` callback like any
  other resource, so a hung OTLP endpoint cannot stall shutdown past the existing global deadline.
- A failed OTLP export degrades to a `telemetry_export_failed` warning (via the existing
  `AgentTelemetryWarningCode` union, extended with this new code) and does **not** fall back to
  writing the dropped span to the local exporter (that would silently change the `local`-vs-`otlp`
  privacy boundary the operator configured).

Performance budget: span creation/attribute resolution must stay off the hot path when
`mode: "off"` (already true — every helper in `telemetry.ts` short-circuits on `telemetry === undefined`
before touching the OTEL API). When enabled, per-span attribute resolution is bounded by the same
`MAX_TELEMETRY_*` constants already enforced for GenAI spans; no unbounded serialization is added.

## 5. Unhandled-error capture contract

The durable local crash record (`postmortem.ts` → `writeCrashRecord`) remains the single source of
truth for fatal capture — it is process-local, synchronous-on-the-fatal-path, and already
redacted/bounded. This design does not replace it; it attaches correlation:

1. `handleFatalError` (`postmortem.ts:527`) gains two additional best-effort fields read from
   module-level state set by the telemetry bootstrap (when telemetry is enabled): the active
   `gjc.session.id` / `gjc.run.id`, and, if a span is active on the OTEL context at fault time, its
   `trace_id`/`span_id`. All three are read via a plain getter with a try/catch — a broken
   accessor must never block `writeCrashRecord`.
2. When `telemetry.export.mode` is `local` or `otlp`, the fatal handler also attempts one bounded,
   best-effort span emission: an `error.type`-tagged event on the active span (or a
   root-span-less `process.crash` span if none is active), with a hard timeout no larger than the
   remaining cleanup budget. This emission is strictly additive — if it fails or times out, the
   already-persisted crash record and journal entry (step 1, which runs first and is synchronous)
   are unaffected. This ordering matches the existing "persist first, best-effort output second"
   comment already in `handleFatalError`.
3. `uncaughtException` / `unhandledRejection` continue to funnel through the existing `Reason`
   enum and `handleFatalError`; no new signal source is introduced.

## 6. Staged implementation plan (design → build order, each stage independently testable)

Every stage below is a candidate follow-up PR once the owner admits it; none is authorized by this
document alone.

1. **Bootstrap + config surface.** `gjc.run.id` minting in the host, `telemetry.export` settings
   schema, `off` mode fully wired end-to-end with a test asserting zero tracer/API calls when off
   (extends the existing `spans: false` contract test surface).
2. **Local exporter.** `local` mode: `TracerProvider` registration, bounded JSON-line span writer,
   attribute-bucket enforcement tests (always-safe/local-only/opt-in/forbidden), size-bound tests.
3. **Cross-process/child correlation.** `traceparent` propagation into spawned child processes
   (`task` isolated mode, tmux/team children); `child_process` and `workflow_gate` span kinds;
   parent/child correlation tests.
4. **Crash correlation.** Steps in §5; tests for: correlation fields present when telemetry is
   active, absent-but-non-crashing when telemetry is inactive, and a broken correlation getter not
   blocking crash persistence.
5. **OTLP exporter.** `otlp` mode, sampling, exporter-outage isolation tests (kill the collector
   mid-run, assert the agent loop and shutdown are unaffected), default-off verification.
6. **Docs + SDK/CLI/TUI/harness parity.** `docs/environment-variables.md` and `docs/sdk-app-guide.md`
   updates, CLI flag/settings docs, packaged-binary dependency check (`build-binary.ts` entrypoint
   list, `verify-docker-context.ts` warning at `scripts/verify-docker-context.ts:124` already exists
   for `generate-docs-index` and should get an analogous check for the new exporter deps).

## 7. Explicit non-goals

- No new duplicate "truth surface" — token-usage JSONL and crash logs keep their existing formats
  and locations; this design adds correlation IDs to them, not a parallel event store.
- No default remote export destination, ever.
- No change to the existing GenAI span content-capture opt-in contract (`packages/agent/src/telemetry.ts`);
  this design extends the same allowlist model to run/session/child-process spans rather than
  replacing it.
