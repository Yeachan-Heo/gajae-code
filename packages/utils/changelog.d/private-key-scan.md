### Fixed

- A base64/token68 auth continuation is masked again. The diagnostic-line guard read the trailing `=` padding as an assignment, so `Basic\nZml4dHVyZTpwYXNzd29yZA==` stayed unchanged; padding is now distinguished from `key=value`. A padded token followed by a diagnostic is split at the token boundary, so `Basic\nZml4dHVyZTpwYXNzd29yZA== diagnostic=keep` masks the token and keeps the diagnostic, while a genuine diagnostic line after a cue is still preserved.
- A wrapped URI after an auth cue keeps its text. `Token\n_https://app:synthetic@db.example.com/db_` used to lose the whole URI to the continuation rule; the guard now accepts any run of wrapper characters, so `Token\n**https://app:synthetic@db.example.com/db**` masks only the userinfo and keeps the wrapper, scheme, host, path and Markdown delimiters.
- An apostrophe in a plain YAML scalar no longer ends a bracketed container early. A quote opens a container value only after `[`, `{`, `,`, `:` or `=`, so `wrapper: [don't, "…"]` keeps its quoted multiline data out of the block-scalar scan and the surrounding document survives.
- A comment shaped like a container assignment no longer opens a container. `# wrapper: ["ignored\nsecret: |\n  …` used to hide the real block scalar below it; the line is ignored when the quoted-data bound is decided, so the body is masked and the surrounding text stays verbatim. An inline comment (`wrapper: visible # wrapper: […]`) ends structural recognition the same way, so it cannot open a phantom quoted container over the real header below it.
- An escaped continuation ends at the next serialized line break. `bearer\nopaquecredential123\ndiagnostic=keep` in a serialized field used to swallow everything after its token; the scan now stops at the next `\n` escape, so only the credential is replaced and the escaped segment structure survives.
- An unpaired private-key banner is detected on the original text and replaced only through the body it owns. A banner with no footer used to erase the rest of a preview, deleting a nested sibling (`note`) or prose after it and leaving invalid JSON; the replacement now stops at the end of the base64 body, so siblings, prose and syntax survive while the credential body is still masked.
- A quoted YAML mapping key is accepted as a container bound, so `"wrapper": ["ordinary\n  secret: |\n    continuation"]` keeps its comment and closing quote instead of being overwritten by a fake header.
- A lower-case `Authorization` scheme is recognized by the full-line fallback, so a trailing diagnostic (`Authorization: bearer … diagnostic=keep`) is no longer deleted with the credential.
- A crash log field is classified in full before its preview is cut. Truncating first dropped the `@` that ends a URL's userinfo and the footer that pairs a private-key block, so a credential lying beyond the 4 KiB preview bound survived; the completed field text is now masked once and then bounded, and a banner with no footer in the whole field masks the rest of that field.
- A captured string field is classified after its escape decoding, so an auth continuation written as `\n` in the payload is masked like a physical line break. A serialized value keeps the escape, so the same cue-and-token shape is also recognized after an escaped break.
- Current crash output classifies once and applies once. `recordFatalCrash` classifies each captured field in full before bounding its preview, classifies the record's header once, and classifies the whole stack once before resolving its frame boundary; the fingerprint consumes the already-masked name, message and stack without running detection again. Masked field text is therefore never fed back into a detector anywhere in the writer.
- A repeated unclosed private-key banner no longer stalls scrubbing. A complete block is still replaced.
- Credential-container scanning is work-bounded, so repeated unclosed `secret={` lines no longer rescan the remaining text each time. A container that closes near the end of the bound is still found, and the line lookup advances forward instead of rescanning the suffix per container.
- Private-key banners pair with the nearest opener before a footer (LIFO), so an opener that sits inside a credential container or YAML body does not pair forward past the real block and swallow the diagnostics in between. An unclosed banner still cannot stall a scan.
- URL userinfo is masked before the Bearer/Basic/Token rule in the same pass. The auth-token rule no longer consumes a scheme word (`Token postgres://…` keeps `postgres://` readable) or a following diagnostic, and it is attempted one physical line at a time. A bare auth cue (`Token`/`Bearer`/`Basic`, recognized case-insensitively) followed by a URI on the next line no longer consumes that URI; the continuation skips a line that starts a URI.
- A private-key block that sits between a URL's scheme and its `@` is masked as the block itself. The userinfo scan stands down for that URL instead of treating the host before the banner as userinfo, so `https://db.example.com(…private key…)@note` keeps `db.example.com` and `@note`.
- A YAML block-scalar header found inside a quoted container value under an ordinary key is treated as data, not a header. The fake header no longer starts a body scan that overwrites the surrounding document's comment and closing quote.
- When the credential-container scan runs out of lookahead, the whole text becomes one redaction marker. Masking only the remaining suffix kept a prefix whose later-rule inputs were gone: the footer a private-key block pairs with, the `@` that ends a URL's userinfo. Losing the diagnostics of text already dominated by unclosed containers is the price of a cutoff that holds for every later rule.

### Changed

- Detection reads a branded `OriginalText` and returns ranges; `applyRedactions` is the only function that produces `RedactedText`. A `RedactedText` is not assignable to `OriginalText`, so feeding masked output back into a detector is a type error rather than a silent reclassification.
- `findCredentialContainerSpans` reports the credential-container ranges of the text it is given without mutating it, so a caller that also detects private-key blocks can apply both to its original text in one pass.
- `findUnpairedPrivateKeyBanner` is replaced by `findUnpairedPrivateKeySpans`, which reports each opener that no footer closes together with the body it owns. Callers apply that range in the same classification pass instead of rescanning masked output and deleting text after the banner.
- `CrashFingerprintOptions.alreadyMasked` lets a caller that persisted already-masked text compute the v2 identity without running detection over its own output again.
- `findUrlCredentialSpans` reports only the userinfo range of a URL, so a caller can keep the scheme and host printed while masking the credential.
- `findYamlBlockScalarSpans` reports the printed body ranges of credential-named block scalars and stops a body discovered inside a credential container at that container's close, so unrelated text after the container survives. A header-shaped line inside a quoted container value under any key is data, not a block scalar, and does not start a body scan.
- `redactStructuredSecrets` only reads a flat name/value array or a `{ name, value }` record as header pairs when the caller opts in, by boolean or by a field-name predicate such as the new `isHeaderCollectionKey`, so ordinary data keeps its values.
- `redactStructuredSecrets` takes a `resolveKey` hook so a caller that decodes names before serializing classifies the credential test, the header-collection test and the header-record member roles by the decoded name. Callers that pass no hook keep the name as given.
