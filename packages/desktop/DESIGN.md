# Gajae Code Desktop

## Brand

The app icon, the sidebar badge and the empty state use the Gajae-Code character that the repository already ships in `assets/character.png`: a warm dark rounded tile with the straw-hat mascot and its visor. `packages/desktop/icon.png` is the tracked 1024 px source; `bun run icons` regenerates `src-tauri/icons/` (gitignored) from it, and `src/assets/gajae-mark.png` is the 256 px tile the renderer shows at 26 px in the sidebar and 88 px in the empty state. Brand art is raster and local: the renderer never fetches a remote image.

## Workflow: EXISTING DESIGN SYSTEM

Extend the existing warm-neutral desktop system, component library and `?showcase` harness. This is not a greenfield redesign. Preserve project organization, parallel conversations, long-running work and reviewable outputs in a first-party GJC interface. Codex-style means compact navigation and a quiet reading/composing workspace, not copied branding, vendor assets or product claims. Historical reference: https://developers.openai.com/codex/app/ (retrieved 2026-10-27; redirected to https://learn.chatgpt.com/docs/app); no third-party material is vendored.

## Layout

Muted 264px left sidebar groups conversations by project, displaying Working/Done/Needs input/Error independently of selection. Its bottom-right toggle switches to a persistent 64px navigation rail: project buttons show the first two Unicode characters, conversation buttons show only status indicators with full accessible names and hover titles, and settings/open-project remain icon actions. The mobile drawer always uses the full layout, regardless of the desktop preference. Each workspace lists five conversations and appends up to five more per `Show more` click; the compact rail uses an ellipsis button for the same pagination. A selected conversation beyond the page keeps its row visible. The page limit lives in the renderer and never changes stored data. Compact toolbar names the selected project/session. Central conversation reading column and sticky bottom composer. Optional right changed-files/diff pane. Settings and command navigation require no terminal. Empty states offer a single primary action.

## Tokens

System sans-serif, 14px (0.875rem) base, line-height 1.55; medium-weight compact headings and 12px secondary metadata. Use rem typography so browser text scaling remains effective. Monospace is reserved for paths, code and tool output. Assistant prose and display reasoning use semantic safe Markdown; user text and tool output keep their original whitespace.

Shape, elevation and motion come from one soft, rounded scale rather than per-component numbers: `--radius-xs` 8px, `--radius-sm` 10px for controls and session rows, `--radius-md` 13px for tabs and nested cards, `--radius-lg` 16px for panels, user messages, question cards and the composer, `--radius-xl` 20px for the modal, `--radius-pill` for chips. `--border-soft` (a 58% tint of the theme border) draws structural edges, `--surface-2` fills inset surfaces, `--shadow-rest`/`--shadow-soft` give controls and overlays a shallow lift, and `--ease`/`--dur` keep transitions at 160ms. Inputs and buttons share the same 10px radius; a focused field swaps its border for the accent and an `--ring` halo instead of an outline. Both dialog tab bars (model picker and settings) share one surface-and-pill pattern with the same raised selected state; the model bar stretches its two tabs to the full width, while the settings bar sizes four tabs to their content and wraps at narrow widths.

Palettes come from the bundled TUI themes (`packages/coding-agent/src/modes/theme/defaults`): red-claw (default), blue-crab, claude-code, codex, gruvbox-dark, opencode and ouroboros. `themes.ts` owns the runtime source: `applyTheme()` writes the selected palette to the document as custom properties before first paint. CSS keeps one static red-claw fallback block so the app is never unstyled before that script runs; that fallback must be kept in sync with `themes.ts` whenever the default palette changes. Every bundled theme is a dark palette, so the desktop follows the selected theme instead of the operating-system color scheme, and `color-scheme: dark` keeps native widgets consistent. Accent hover, accent tints and error tints derive from `color-mix` rather than hand-tuned duplicates. Theme choice is a browser-local display preference stored under `gjc.desktop.theme`; it never writes shared terminal configuration, and unknown or blocked storage falls back to red-claw.

Execution status uses four fixed hues that stay distinguishable on every palette: Working blue `--status-running`, Done green `--status-done`, Needs input amber `--status-waiting`, Error red `--status-error`; Idle stays muted. These are deliberately independent of `--accent`, because the default red-claw accent is already orange-red and would erase the difference between a running turn, a question and a failure. Sidebar status rows pair hue with icon and text; the conversation header repeats the same words without the icon, so a settled session reads Done above the transcript instead of Idle.

- `.composer` starts at one line and grows with wrapped text/newlines up to a bounded internal scroll region. Enter sends; Shift+Enter inserts a newline; IME composition and modified Enter never submit. The optional `attachment` slot places the accessible icon-only picker left of the prompt, with actual chips/errors below; paste remains on the textarea. Remove passive paste boxes and redundant shortcuts/format-limit helper prose. `.composer` owns only the draft and the send/stop keyboard behavior. Optional `controls?: ReactNode` renders inside `.composer-controls`, a named accessible group on the same `.composer-footer` line as `.composer-actions`; no row is rendered when omitted. Slot owners provide labeled controls, pending/disabled behavior and real operations. `.composer-footer` is top-aligned and `.composer-controls` uses a zero flex basis, so the model and reasoning controls, and the single `.composer-action`, always share one line while the controls' own content wraps underneath. There is no delivery selector: a prompt typed during a run is queued and steered into that run, as in the TUI, and `deliverAs` stays `steer` in the wire request. `.composer-action` is exactly one icon-only button (accessible label `Send`/`Send and steer the run`/`Stop`, no visible text): it stops the turn whenever the session is running and the draft cannot be sent — empty, blocked, operator-owned or holding a not-ready attachment — otherwise it submits. Stop ignores activation for 600 ms after a submit so the send-to-stop swap cannot abort a run under an impatient second click. There is no separate keyboard stop on the composer. Textarea, controls and action groups shrink/wrap without page overflow. No model/provider fixtures belong in product components.
- Model/reasoning presentation hooks are `.model-controls`, `.model-trigger`, `.reasoning-control` and `.model-control-status`. The `.model-dialog` opens on two tabs (`.model-tabs`, `.model-tab`): Presets lists every registered model profile with its per-role model selectors in `.preset-roles` and asks for session/default scope before applying a profile; Models is the searchable catalog. Each tab keeps its own query, and ordering/filtering never crosses tabs. `.model-toolbar` pairs `.model-search` with an icon-only `.model-refresh` (aria-label `Refresh the model list`) so list refresh lives inside the dialog instead of the composer. A model row is one bordered `.model-option` box containing the `.model-option-hit` button and, at its right edge, the `.model-favorite` star cell; no button is nested inside another, and starring never selects the model. The selected model is conveyed only by `aria-current` on the row plus the hit button's accessible state — no second checkmark. `.model-option-main` presents name, provider/ID and role tags; tags show the role label alone, never an inheritance suffix. The picker renders every available model without a load-more cap. Selecting a model first opens Default/Executor/Planner/Critic/Architect target choices, never immediately mutates Default. Presets apply by profile id, never by display name, because the host validates the registered profile identity. A session that is running, waiting or operator-owned keeps every preset row and role action available: those writes take the host's exclusive lock, so the renderer holds the choice and dispatches it after the session settles instead of disabling the control or printing a reason. The dialog itself is never dismissed by catalog loading, refresh, a catalog error, or a disconnected trigger, so the in-dialog refresh control always has a retry path.
Assigned models appear first in that role order, then browser-local favorites, then original catalog order; all matching role tags remain visible. Default-role model selection and preset selection lead to `.model-scope-choice`, with explicit `Current session only` and `Set as default` buttons. No mutation occurs before confirmation. Session model selection uses `model.set`; durable model selection uses the existing default-role preferences operation. Unavailable persistence disables only the durable choice and exposes its reason. Cancel/Back/Escape never dispatch, and replacing a session owner retires the confirmation. Task-role choices belong to the live session and clearing reveals inherited configuration. Model, reasoning, profile and role controls stay enabled while a turn runs and take effect from the next request; no sentence explains that timing to the user. Because the SDK serializes default-model selection and preference writes behind its own fence, the renderer holds one intent `{modelId?, thinkingLevel?, preference?}` while the session is busy and applies it once the session is truly settled: status is not `running` or `waiting`, no operator owns the session, and no queued input remains. A host `error` status counts as settled, matching the host's own exclusivity rule, so a failing turn never strands the intent. A chosen model or reasoning level shows immediately and stays visible until the host answers; a chosen preset or role shows once the host confirms it, because the picker's active state is host-derived. Only the dispatch waits, and a rejected deferred request renders its error in the model controls and in the preferences dialog. A profile or role change lands before any model choice in the same intent, so an explicit model is not overwritten by the mapping a profile reintroduces. A pending model and reasoning choice merge into one `model.set` carrying both only when the target model declares that level; otherwise the model change is committed first and the level follows as its own request so the host's real reason surfaces. Contention on the same scope is retried instead of dropped, and a retired session generation clears the intent with a notice rather than applying it elsewhere. It never claims the value changed before the host confirms it and never sends a second request for the same choice. The intent is keyed by session and control generation and is retired with a notice as soon as either changes, so it can never apply to another conversation or a retired generation. Issuing the request mid-turn would make queued follow-ups wait behind a selection that itself waits for idle, so it is deliberately deferred instead. The model and reasoning controls share one dropdown language: `.select-control`/`.select-trigger`/`.select-menu`/`.select-option` keeps every custom trigger at the model trigger's height and radius instead of an OS menu, and `ReasoningSelect` anchors its menu in viewport coordinates because the composer pane clips absolute children. ## Language

The first release ships English only. Renderer copy lives in `src/i18n/en/` as a flat `as const` catalog (`shell.*`, `support.*`, `models.*`, `panels.*`, `settings.*`, `showcase.*`), and components resolve it through `t("area.key")` from `src/i18n/index.ts`; a missing key fails typecheck, and `t()` falls back to English when the active locale has no catalog. `src/components.tsx` is the reference conversion. Two categories are deliberately outside the catalog: host-issued prose (tool display names, reason text) is literal English in `packages/desktop-host`, and a few protocol-shaped values (ids, provider names, settings keys) are shown verbatim because they are identifiers, not copy.

Locale plumbing is deliberately ahead of the copy: the code set, the persisted key `gjc.desktop.locale` and the fallback shared with the TUI (`en`, `ko`, `zh`, `ja`), plus `setLocale`/`subscribeLocale`/`availableLocales()` and a `useLocale()` subscription in the app root and the showcase. Only `en` carries a catalog, so `availableLocales()` reports one locale and no language switch is offered yet. Adding a language means a new `src/i18n/<code>/` catalog registered in `catalogs`; because the roots already subscribe, that needs no call-site edits and no migration for a stored preference, and `setLocale()` then re-renders the tree.

The host and the native shell stay English-only: `packages/desktop-host` emits literal English transcript and reason text, and protocol values, ids, storage keys and theme ids are never translated.

### Workspace layout and session-state panels

Workspaces and conversations are ordered by the host catalog, not by the renderer: `project.reorder` and `session.reorder` persist an explicit permutation of what the snapshot shows, splicing closed workspaces back into the slots they occupy, and the desktop drags rows (with an insertion cue on the target) or uses the menu's `Move … up`/`Move … down` items, which are the keyboard-reachable path for the same order. Both paths are disabled while a search filter is active, because a filtered list cannot name the permutation the host stores. Starring marks a conversation and never re-sorts it. A rejected permutation (`Invalid project order`/`Invalid session order`) restores the previous array, so an out-of-date list cannot half-apply.

Right-clicking a workspace, or pressing ContextMenu/Shift+F10 on its heading or a conversation, opens `.context-menu` over a dismissing `.menu-scrim`; the menu takes focus, Escape closes it before the drawer, it is clamped inside the window, and move items are disabled at the ends of the list. Inside the drawer the menu is rendered within that modal dialog, because a top-layer dialog would paint over a sibling overlay. `Close workspace` sends `project.close`, which marks the catalog entry `closed`: the workspace and its conversations leave the snapshot, its live session is retired, and the directory, session files and metadata are never deleted. The closed flag is persisted, so it survives a restart; a closed workspace's conversations are not addressable until it reopens. `project.open` on the same path clears the flag and restores the same project identity, so reopening a closed workspace brings its conversations back instead of orphaning them under a new id. Open and close for one path are serialized: a reopen issued while a close is still retiring conversations waits for that teardown instead of observing a half-closed workspace, and the durable close publishes before the teardown so the workspace leaves the list immediately.

Builtin tools that own durable session state project it, rather than leaving it inside a tool result. `todo_write` becomes `DesktopSession.todos` (`getTodoPhases()`, capped at 24 phases/120 tasks/300 characters per item, so a pathological list is bounded rather than complete) rendered as `.todo-panel`: collapsed it states `done/total tasks done` plus the task in flight, expanded it lists the reported phases and tasks with status icons. The `goal` tool becomes `DesktopSession.goal` (`getGoalModeState()`) rendered as `.goal-strip` with the objective, its status and only the operations that status allows (pause/complete/drop while active, resume/drop while paused, drop when finished). A goal with an unrecognised status or an empty objective is omitted rather than defaulted, and each usage number is dropped on its own when it is absent or negative; the strip's actions are disabled while a turn owns the session and its refusal is shown beside it; the Manage goal dialog applies the same state rule, and the command palette disables that command while a turn or a waiting session owns the conversation. Both panels sit between the transcript and the composer, are omitted entirely when the session has no todos or goal, and never invent state the SDK did not report. The desktop session is built from the full builtin registry with no reduced tool list, so `tools.list` reports every tool the SDK exposes and `tools.set` validates a selection against that same registry; each tool still applies its own settings and platform guard (a disabled renderer or a missing `gh` keeps its tool inert), and interactive tools keep their existing surfaces (`ask` kinds in `QuestionCard`, `resolve`/approval in `GateDialog`, MCP in `McpPanel`).

Session names come from the SDK's first-accepted-input automatic-title operation. `New session` is a catalog display placeholder, never a user-sourced transcript title. Manual renames win, retired owners cannot apply late generation, and a committed SDK title remains authoritative if its redundant catalog cache write fails; reopening reconciles that cache. Title work never changes delivery disposition.

## Account authorization

The app uses public AuthStorage login callbacks with a single app-owned authorization flow. Provider selection, an explicit HTTPS-only system-browser action, optional code prompts, cancellation and reopening settings are supported. Prompt answers are never persisted in frontend storage. Cancellation does not undo credentials a provider already saved; an uncooperative provider may require Quit and relaunch before another login. This is not proof of a completed real-provider login.

Before the SDK captures environment state, the sidecar strips inherited provider keys/tokens, routing/proxy overrides and CLI broker state. Shared mode restores the installation's HOME and resolved agent directory (including explicit agent-directory overrides); credentials remain in the SDK's shared storage, not a new Keychain implementation. `GJC_DESKTOP_ISOLATED=1` instead places HOME, agent, configuration and XDG roots under the app data directory for tests/QA. Neither mode is an execution sandbox for SDK tools.

## Delivery recovery and process ownership

Before clearing the composer, atomically retain its original text and ready attachment payloads in local IndexedDB. The host retains metadata-only delivery receipts and acknowledgment tombstones. Durable handoff and SDK preflight acceptance are not proof that a model run executed. Definitive refusal is distinct from provider failure, cancellation, and an unknown outcome; a disconnect or restart must never automatically replay potentially executed input.

Normal pending, accepted and queued delivery receipts remain durable internal bookkeeping, not recovery warnings; reconcile bootstrap receipts before exposing an unmatched record as unknown. Successful completion/cancellation and automatic definitive-refusal restoration do not flash alarming cards. Actionable unknown outcomes explain possible prior execution; failed outcomes use distinct copy without promising that execution never started. Known-unsent storage repair remains separate from acknowledgment failure. Unknown/failed recovery requires an explicit user action; definitive refusal/removal restores safely without replay. Restore preserves newer draft text and attachments; acknowledging the recovery record does not erase the restored draft. Network acknowledgment is bounded and does not hold the local draft-write queue. Repair and disposal controls belong to an exact delivery ID, not every delivery in the same session; unresolved known-unsent repair cannot be discarded.

The process entrypoint registers host teardown and final frame draining with the shared signal-exit owner. It does not race an independent LSP exit handler or remove unrelated signal listeners. Protocol-requested shutdown is a normal zero exit; SIGTERM retains the shared conventional status. Signal cleanup remains bounded by the existing postmortem deadline (5 seconds by default, configurable with `GJC_CLEANUP_DEADLINE_MS`); expiry can interrupt teardown or final frame flushing, so it is not a guaranteed-delivery contract. Unproven deliveries remain recoverable as unknown. QA fixtures use the same process lifecycle and observe real MCP transport termination and LSP process exit rather than inferring teardown from a stale-session error.
