### Added

- When a terminal already has a conversation open, the app now shows that conversation read-only. It checks before opening the conversation, before each message or other change it makes, and when you select it, so the two do not write to it at the same time as long as the check can see the terminal: a check can see the terminal only while a gjc broker is running (an interactive terminal normally starts one), and a terminal that opens the conversation just after a check, or while the app's turn is already running, is caught at the next one. Its history stays visible, the composer is replaced by an explanation with a "Check again" button, and the sidebar and header say it is in use in a terminal. While the conversation's own background work is running, the app keeps it open instead, so that work is not ended, and refuses to start anything new in it until the work ends or you disconnect it. Once the terminal closes it, selecting the conversation or "Check again" takes it back. When the app cannot check, it opens or writes the conversation as before, and a write that collides with the terminal's is refused rather than lost.
