### Added

- When a terminal already has a conversation open, the app now shows that conversation read-only. It checks before opening the conversation, before each message or other change it makes, and when you select it. Its history stays visible, the composer is replaced by an explanation with a "Check again" button, and the sidebar and header say it is in use in a terminal. While the conversation's own background work is running, the app keeps it open instead, so that work is not ended, and refuses what you send until the work ends, you stop it in the Session work panel, or you disconnect the conversation; when the work finishes, the app can still add its result and a reply on its own. Once the terminal closes it, selecting the conversation or "Check again" takes it back.
- The check sees a terminal only while a gjc broker is running (an interactive terminal normally starts one) and answers within half a second; otherwise the app opens or writes the conversation as before. Some cases are not caught: the terminal opens the conversation while the app's turn is running or between the app's check and its write, no broker is running or the check does not answer in time, or the app starts a turn by itself when the conversation's background work finishes. If both sides then write, a message the app sends from an older position is refused (its text comes back and the app reloads the conversation), and so is a non-interactive terminal run's (`gjc -p`). An interactive terminal that writes from an older position is not refused: its message starts a separate branch, the app then shows the terminal's branch, and what the app wrote in that window stays in the conversation's file on the other branch but is no longer shown. To avoid this, Disconnect the conversation in the app before continuing it in a terminal.
