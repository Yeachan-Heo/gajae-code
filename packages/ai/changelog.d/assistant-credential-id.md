### Added

- `AssistantMessage.credentialId` records the stored credential row that authenticated the request producing the message. `streamSimple` stamps `StreamOptions.credentialId` on every partial, the `done` or `error` message, and the stream result; an auth retry that returns an `AuthRetryCredential` with its own `credentialId` attributes the retried response to that row, while a bare replacement key leaves the field unset. The value is the opaque, non-secret row id only, and it is never set for external, env, or pi-native gateway keys. Attribution is best-effort and never fails a request whose message object rejects the write. An attributed request now aborts its provider request when the consumer stops iterating early, matching the auth-retry path. `pi-native-client` never sends a `credentialId` to the gateway, neither the request option nor the field on prior assistant messages in the context. `stripCredentialIds(messages)` removes the field from assistant messages before a context leaves the process. On signing Anthropic endpoints `credentialId` also gates thinking replay: an earlier turn's signed or redacted thinking minted under another stored credential is dropped, and a latest turn minted under another credential makes the request replay no native thinking, as the existing unreplayable-thinking repair does.
