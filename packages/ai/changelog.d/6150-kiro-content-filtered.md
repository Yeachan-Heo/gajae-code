### Fixed

- Kiro streams now surface explicit content-filter refusal messages with category and explanation instead of the generic "no tokens" error when a refusal is detected. Both bearer token (via `messageMetadataEvent`) and API-key (`ksk_`, via `metadataEvent`) paths are supported, with proper provider safety-stop minting. API-key text is quarantined until successful terminal metadata (`COMPLETED`/`TOOL_USE`) or clean EOF, so a refusal across any number of response chunks suppresses all text; successful text is emitted before HTTP EOF once terminal metadata arrives. A preceding thinking block still defers text to preserve block order. Tool calls are emitted only at stream end (#6150).
