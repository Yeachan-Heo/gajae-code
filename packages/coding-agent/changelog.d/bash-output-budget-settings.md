### Changed

- The Bash tool now reads its inline output retention from dedicated settings, `tools.bashOutputTailBytes` (default 1 KB) and `tools.bashOutputHeadBytes` (default 0, tail only), instead of overloading the shared `tools.artifactTailBytes` / `tools.artifactHeadBytes` keys. The shared keys previously showed a 20 KB default in `/settings` and `gjc config get` while Bash silently used 1 KB unless the key was physically present in `config.yml`, so re-selecting the displayed default changed Bash behavior. The shared keys no longer affect Bash output anywhere: Bash results carry their retention policy, so the Bash capture window, the threshold spill, and the inline-size backstop all shape a Bash excerpt from the Bash keys — including Bash output returned through `recipe` — and the backstop caps head and tail independently inside the shared `tools.maxInlineResultBytes` size cap instead of letting the cap widen a 1 KB tail. **Migration:** any `tools.artifactTailBytes` / `tools.artifactHeadBytes` value you set for Bash — whether it widened output or restricted it (for example `0` or another value below 1 KB) — must be copied to `tools.bashOutputTailBytes` / `tools.bashOutputHeadBytes`; otherwise Bash returns to its 1 KB tail-only default after upgrading. The shared keys keep governing every other tool's spill.
