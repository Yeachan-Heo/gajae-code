### Added

- Added implicit, keyless Rapid-MLX discovery at `http://localhost:8000/v1`, explicit `discovery.type: rapid-mlx` configuration, and served context-window metadata. Implicit and dedicated Rapid-MLX discovery aborts after 500 ms over the direct socket, which does not follow redirects, so an unresponsive or redirecting server cannot stall startup or forward `RAPID_MLX_API_KEY`. A credentialed loopback probe goes over a direct socket, so `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` (including a proxy a project `.env` declared) never receives the bearer. The implicit probe only publishes entries that carry a Rapid-MLX-native field, so a vLLM-only server on port 8000 keeps its own `vllm` catalog, and that admission policy is part of the discovery cache provenance; an `offline` refresh republishes the cache only while the cached row was admitted under the current policy.
- Rapid-MLX completions use the same direct loopback transport as discovery, so a configured `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` never receives the bearer or the request body. Keyless `/models` probes use it too, so a proxy cannot answer discovery and inject a catalog. A non-loopback endpoint keeps the normal proxy-aware transport, and the implicit vLLM/SGLang probes skip individual entries that carry a Rapid-MLX-native field.
- Rapid-MLX inference on the `openai-responses` api uses the same direct loopback transport, so that supported path cannot forward the bearer or the request body to a proxy either. A loopback vLLM/SGLang catalog cached before the reciprocal identity guard is refused on an `offline` refresh instead of being republished.
