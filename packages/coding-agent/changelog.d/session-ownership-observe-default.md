### Changed

- Session ownership now defaults to `observe` (`session.ownership.mode`). Each gjc process that opens a session for writing takes a claim on it, and a session that another process already holds is counted as a conflict. `observe` never refuses anything and shows no warning (the log records it): both processes keep working exactly as before, with one exception: a fork of a session held elsewhere whose transcript is still in the legacy location reads it in place instead of migrating it. `gjc session owners` lists the sessions held right now, and `gjc stats --summary` / `gjc stats --json` show the counts (`claim_taken`, `claim_conflict`, `held_at_exit`, and others) once processes exit cleanly. A claim that cannot lock fails open: on Windows, which has no native lock yet, every claim does (sessions open without a claim, `gjc session owners` stays empty, and each attempt counts `fail_open`), and one lock timeout, for example on a stalled network filesystem, turns claims off for the rest of that process, so opens never wait for the lock more than once. Writes after a fail-open claim are not counted as `session_write_without_claim`. To turn it off, run `gjc config set session.ownership.mode off`, which writes the global config; an unreadable config counts as `off` and is retried on the next open. `GJC_SESSION_OWNERSHIP=off` in your shell lowers the mode for processes started from that shell only: it cannot raise the mode, a project `.env` cannot set it, and hosts launched by the SDK broker (ACP, `gjc sdk`, daemon sessions) take the broker's environment, not your shell's, so use `config.yml` for them. Restart running gjc processes after changing the mode: a running TUI keeps claiming under the mode it started with, even on Linux, where it hot-reloads other settings. See `docs/session.md`.
- `gjc doctor` now warns about session owner sidecars only above 100,000 (was 10,000). Sidecar pruning is not implemented yet: one empty sidecar per session ever opened accumulates. They are harmless; do not delete them by hand while gjc runs.
