### Changed

- Session ownership now defaults to `observe` (`session.ownership.mode`). Each gjc process that opens a session for writing takes a claim on it, and a session that another process already holds is counted as a conflict. `observe` never refuses anything and shows no warning (the log records it): both processes keep working exactly as before. `gjc session owners` lists the sessions held right now, and `gjc stats --summary` / `gjc stats --json` show the counts (`claim_taken`, `claim_conflict`, `held_at_exit`, and others) once processes exit cleanly. On Windows there is no native lock yet, so every claim fails open: sessions open without a claim, `gjc session owners` stays empty, and each attempt counts `fail_open`. To turn it off, run `gjc config set session.ownership.mode off`, which writes the global config; an unreadable config counts as `off` and is retried on the next open. `GJC_SESSION_OWNERSHIP=off` in your shell lowers the mode for processes started from that shell only: it cannot raise the mode, a project `.env` cannot set it, and hosts launched by the SDK broker (ACP, `gjc sdk`, daemon sessions) take the broker's environment, not your shell's, so use `config.yml` for them. Restart running gjc processes after changing the mode: a running TUI keeps claiming under the mode it started with, even on Linux, where it hot-reloads other settings. See `docs/session.md`.
