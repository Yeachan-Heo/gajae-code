### Changed

- With `session.ownership.mode: enforce` (not the default), gjc no longer opens a session that another process holds for writing, and refuses before anything is written to it. `gjc -p --resume <id>` and `gjc -p --continue` print the holder and a `gjc -p --fork <id>` command on stderr and exit non-zero, before any model call; without a terminal, an interactive `gjc --resume <id>` refuses the same way. `gjc --continue` in the TUI and `autoResume` (also with `-p`) start a new session instead and say why. `SessionManager.open`, `openExistingStrict`, `continueRecent` and `createAgentSession` throw an error with `code: "session_held"` that names the holder. A fork never refuses its source, an owners directory that fails its safety checks refuses the session, and remote clients (ACP `session/load`, `gjc sdk`) still attach to the holder. Each refusal rereads `config.yml`, so `gjc config set session.ownership.mode off` (or `observe`) stops refusals in running processes at once; a file that names no mode, or cannot be read, keeps them. `observe` and `off` behave as before.
