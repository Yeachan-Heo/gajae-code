### Fixed

- `turn.abort_and_prompt` now follows the same ownership rule as `turn.abort`. A connection that does not own the active run, such as another client's prompt or a turn started in the interactive terminal, no longer stops that run. Its replacement text is queued as a steer for the run instead, and the result reports `aborted: false` with `queuedAs: "steer"`. A retry with the same idempotency key returns that steer instead of queueing the text again. The replacement no longer cancels another connection's pending prompt preflight either. An owner's replacement behaves as before.
- `gjc_coordinator_send_prompt` with `force: true` no longer records a replacement turn when the runtime degrades the replacement to a steer. The previous active turn stays active, no new turn is created, and the response reports `delivery: "steer"` and `aborted: false`.
