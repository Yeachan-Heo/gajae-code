### Fixed

- Managed tmux children on macOS pass pre-CLI admission instead of always exiting 75 with `exact_child_binding_unavailable`: the CLI now reads its private child binding through the bounded native owner-only reader, and Broker-redacted launches publish an opaque (command-free) binding instead of none.
- Managed-owner admission handoffs and supervisor bindings are only published through retained private authority; unsafe or missing lifecycle storage blocks the child with a bounded `handoff_not_persisted` diagnostic instead of a pathname write.
- Supervised managed tmux launches from a workspace reached through a symlink (including a symlinked `.gjc`) no longer fail lifecycle verification with `gjc_tmux_managed_storage_unsafe` or `managed_owner_storage_unsafe`: the derived state path names the workspace canonically.
- Managed tmux/psmux launches on Windows are rejected with `gjc_tmux_managed_launch_platform_unsupported:win32` before any lifecycle storage or supervisor allocation, since managed admission needs the owner-only reader that Windows lacks. Windows Broker `session.spawn` (including custom trusted hosts) therefore selects the identity-fenced headless substrate before any multiplexer probe, so it keeps starting instead of failing with `substrate_proof_failed`. Its headless proof is still flushed and exclusively created on Windows, but skips the directory flush Windows cannot perform, as lifecycle storage already does.
- No-replace managed publication on filesystems without atomic no-replace rename (the link fallback, for example NFS) now syncs the directory after removing its staging link, so a crash cannot restore that link and leave owner evidence rejected as a hard link.
- Closing a Broker-spawned headless child now asks the exact registration-pinned host to close itself over its authenticated endpoint, using the Broker lifecycle marker it was launched with, and waits for that exact process to exit before any substrate signal. On Windows the substrate signal is `TerminateProcess`, so a normal close no longer skips the host's endpoint removal and `session.dispose` cleanup; a host that refuses, is unreachable, or does not exit within its cleanup deadline is still closed through the exact substrate escalation.
