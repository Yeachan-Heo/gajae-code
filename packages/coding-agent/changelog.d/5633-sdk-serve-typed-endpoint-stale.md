### Fixed

- `gjc sdk serve` no longer surfaces a session-selection failure as an uncaught exception with the failure code buried in a message string. Selection failures (`not_found`, `ambiguous_session`, `endpoint_stale`, `no_live_endpoint`, `multiple_live_endpoints`) and the broker-reach failures on the same path now raise a typed error carrying a stable `code`, a broker `SdkClientError` keeps both its `code` and its `details` instead of being downgraded, and the command boundary writes a `{"ok":false,"error":{"code","message"}}` envelope to stderr — never the stdout frame channel — and exits 1 (#5633).
- `gjc sdk serve` no longer lets broker teardown replace the failure it is reporting. A rejected `broker.close()` in the cleanup path used to overwrite the typed serve error with its own; the primary failure now always wins and the teardown failure rides alongside it as `cleanupError`. When teardown is the only thing that failed, it surfaces as a typed `serve_cleanup_failed` instead of an untyped rejection, and teardown still always runs (#5633).
- `gjc sdk serve` no longer escapes untyped when the broker discovery record itself is unreadable. A permission, file-kind, or unsupported-state-version failure reading `<agent dir>/sdk/broker.json` used to throw past the command boundary with no stderr envelope and no exit code; it now raises the typed `broker_discovery_unreadable` with the record's path in `details`, never its token. A missing record still reports `broker_unavailable` (#5633).
- `gjc sdk serve` no longer starts a relay on an endpoint record with an empty credential. A missing, non-string, or empty `token` used to become `""` and be written into the upstream WebSocket URL, where it resurfaced much later as a generic transport failure; it is now refused at the broker boundary with the same typed `unavailable` failure an invalid `url` already produces, before either the stdio or the socket relay starts (#5633).
- The `gjc sdk serve` stderr envelope no longer drops the broker-teardown diagnostics it records. When a serve failure and a failing `broker.close()` coincide, the envelope now carries `error.cleanupError` alongside `code`, `message` and `details`, so an embedder can see that the session may not have been released cleanly. An envelope with no teardown failure is unchanged — the key is absent, not present and empty (#5633).
