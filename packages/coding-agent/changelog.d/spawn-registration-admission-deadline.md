### Fixed

- `gjc sdk spawn` no longer rejects a child host that registered and published readiness in time with `child_registration_timeout` just because the broker observed it late. A session index read that began within the 8 s admission deadline is evaluated against the full identity, authority and liveness check, waiting in the index queue or on the index lock is bounded by the remaining budget, and each poll projects only the awaited child. When no registration row was observed in time but the host published readiness, is still live and wrote no failure receipt, the broker takes one more bounded observation (up to 8 s after the first observation ends) under the same checks, so index lock contention that outlasts the first observation by up to that much no longer rejects a timely host. A registration observed after the deadline is admitted only when the host's readiness marker is present on two reads at least one poll apart, the second no earlier than the broker's termination start, with the owner still live and no failure receipt. A host that rolled back at its cutoff is reported as `child_registration_failed` when its failure receipt is observed before the broker settles the spawn, and as `child_registration_timeout` otherwise.
- A `child_registration_timeout` failure message now says whether no registration row was observed near the deadline, a row was observed but did not match the launched host, the session index could not be read in time, or the host registered but never confirmed readiness, and notes when a post-deadline recheck was taken.
