### Fixed

- `gjc --export` can export transcripts larger than 128 MiB again, up to the 2 GiB session-memory limit, without writing anything to the source (not on Windows, which still refuses transcripts above 128 MiB). Their session-memory sidecars are built in a private cache directory under the agent dir, which is removed when the export finishes, fails or is interrupted. Before, export built these sidecars in the session's artifact directory (in the managed store for default-store sessions) and left them there, so only the first export succeeded. Export reflects the transcript as it was when the export started: lines appended during the export are left out, and a transcript replaced or truncated mid-export is refused. As before, only linear, compacted transcripts without patch records can be exported at this size. Any other transcript is refused with an error that names the reason, and a session that was being written while the export read it gets a "retry when the session is idle" error.
- A failed or interrupted HTML export no longer leaves a truncated file at the output path or overwrites a previous export there. The page is now written to a temp file beside the output and renamed into place only when complete.
