### Fixed

- Fixed `/resume` hashing every managed transcript in full each time it lists sessions (#7978). A listing now identifies each candidate by its header and no-follow stat identity (device, inode, link count, size, mtime, ctime). It hashes a candidate only when a retired tombstone or a committed migration receipt names that stat identity, so retirement and migration are still decided on the content digest. Opening, deleting and adopting a candidate hash it at that moment and refuse it with `source_changed` when any stat field differs from the listing, so a file swapped after listing is not opened. A metadata-only change such as a chmod or an xattr write is refused the same way, because ctime is then the only proof that the bytes are unchanged; every open, delete and adopt path lists again right before it binds, so `/resume` still opens a session whose metadata changed while the picker was open. The SDK session-directory listing still returns a digest for every candidate. Listing 772 sessions (1.37 GB) took about 6.6 s and now takes about 2.1 s.
