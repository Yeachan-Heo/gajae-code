### Fixed

- `gjc sdk session list` now bounds broker and scope warnings to 10 total entries, including samples and summaries with exact omission totals. Missing workspace locators produce bounded warnings for `--scope cwd` as well as repository and worktree scopes; `--scope all` still emits no scope-exclusion warnings. (#5051)
- `gjc --worktree` setup refusals now use typed guard errors, print actionable diagnostics, and exit 1 without an uncaught-exception stack or crash-log entry. Diagnostics retain their error-code prefixes and JSON-escape terminal-control bytes; unrelated failures retain the crash path. Help and integration guidance now describe the repo-local `{repo}/.worktrees` default rather than a sibling worktree. (#5051)
- Failed tmux force-close attempts no longer permanently wedge a live owner generation. Authenticated cancelled, expired, and abandoned expired pending intents are archived before retry; consumed, invalidated, live pending, and already-dispatched intents remain fenced. A late matching observer consumes an already-dispatched intent instead of authorizing another close. (#5051)
- `gjc session <action> --json` now exits non-zero when its unchanged response reports `{"ok":false}`, while successful reads still exit 0. (#5051)
- Public tmux lifecycle mutations now require a supervisor-held per-invocation pipe registered to the exact adapter PID/start time and creator-captured owner, monitor, pane, session, and server incarnations. Pane metadata and child-writable token digests no longer grant authority; forged FIFOs, duplicated descriptors, exec-preserving children, and `CLONE_PARENT` workloads cannot mint it. Generation publication and the immutable started receipt complete before untrusted work starts. (#5051)
- Managed tmux launches stage owner generations before supervisor startup, retain early terminal evidence, and refuse to publish an already-dead owner. Supervisors require parent-published authority and wait boundedly for their exact generation before starting work; nested inherited invocations cannot publish lifecycle state. Linux child PID/start-time checks and native Windows pane-wrapper identity binding preserve platform-specific process authority, and an early SIGTERM remains forwarded through a transient child-provenance gap instead of waiting for the child to exit first. (#5051)
- Managed-owner predecessor reconciliation retains lifecycle-root authority across baseline capture, evidence reads, enumeration, and generation publication. Linux and macOS retain native directory descriptors and compare file identities; Windows retains no-delete-share handles for the root and ancestors. Root ABA swaps, identical-content file replacement, unreadable or symlinked generation records, and mixed-root evidence fail closed. (#5051)
- Authenticated replacement owners and replacement launch failures adopt and restamp same-session predecessor runtime markers while stale writers remain fenced. Redacted children retain command-independent terminal evidence, and launch-failure writes retain the published owner generation. Oversized scoped-bootstrap envelopes are rejected before recording an attempt. (#5051)
- Terminal runtime readers accept current bounded markers up to 256 KiB and pre-budget markers through a finite 16 MiB compatibility window, while assistant final responses are UTF-8 bounded at 128 KiB and the complete escaped signed serialization stays within the current reader budget with accurate truncation metadata. Early force-close finalization uses the tmux-tagged project path when the bootstrap seed has no `cwd`. (#5051)
- Vanished-owner probes preserve immutable native tmux `$N` session handles. Raw monitor admission uses provider-aware exact targets and distinguishes confirmed absence from probe failure; discovery and GC treat untagged external names as opaque data before applying strict owned-target syntax. (#5051)
- Owner and monitor adapters receive the resolved tmux command explicitly. The default monitor constructs its exact identity predicate before conditional tagging, and raw supervision preserves terminal verdicts for signals pending between publication and workload startup without admitting arbitrary child observations. Session receipt publication remains compatible with Python 3.8. (#5051)
- Owner-isolation regressions now follow the implemented Linux versus non-Linux topology contract. Missing-provenance and live transition-claim timeout cases carry explicit 15-second budgets, and the inert coordinator discovery fixture remains live through high-cardinality durability tests. (#5051)
- The public session-creation script normalizes a relative `GJC_SESSION_STATE_DIR` override against its invocation directory before entering the absolute-path owner-isolation protocol. (#5051)
- Native Windows managed launches use their already-validated provisional psmux authority for the pre-publication pane PID proof, avoiding a circular requirement that the staged generation already be current. (#5051)
- Managed-owner supervisors publish unexpected-owner-loss evidence when a child exits with status 75; the reserved status is no longer mistaken for a clean cleanup result.
