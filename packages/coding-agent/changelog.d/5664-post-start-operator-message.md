### Fixed

- A post-start prompt failure classified `provider_transport` now says so in operator-facing wording instead of reading as a failure of the user's task. The reported `server_is_overloaded` case surfaced only as `Internal error: Provider failure after execution started.`, which names no cause an operator can act on; the failure payload now carries an `operatorMessage` stating that the model provider ended the turn. The wording is assembled solely from the bounded safe classifier tokens — the category and a `providerCode` that passes `isSafePromptFailureCode` — so no provider text reaches the wire. The JSON-RPC code, the `code`/`details` pair, and every `PROMPT_FAILURE_MESSAGE_*` constant are unchanged, and the message travels alongside them rather than replacing them. Failures in any other category are unchanged: their `phase` and `category` already describe them, so no prose is added. Retry behaviour is unchanged.
