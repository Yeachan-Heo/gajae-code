### Fixed

- Fixed `/resume` copying the transcripts it scans for header patches. The scan reads backward until it finds the header fields it needs, which for most transcripts means reading to the start of the file. It joined each 64 KiB chunk to the carried partial line and searched both the joined bytes and the raw chunk for the marker. It now searches the chunk and the partial line separately and joins them for parsing only when the marker text appears in them. Partial lines at chunk edges, including lines longer than a chunk, are still copied so they can be completed. Scanning 655 transcripts (1.29 GB) took about 1.9 s before and about 1.1 s after. Listing 772 sessions went from about 11.2 s to 10.5 s, and from about 6.6 s to 5.9 s with #7973 applied. The same header patches are found.
