### Fixed

- Closing the window or killing the process during a Windows install no longer leaves `.gjc-install.lock` behind to block every later install with "Another GJC installer is already running". The installer holds the lock open with `DeleteOnClose` for the whole install, so Windows removes it however the installer ends, and a running installer still refuses others. A lock left by an older installer is reclaimed only when its recorded process has exited.
- The Windows installer can now replace a `gjc.exe` that is running. It renames the old binary aside and moves the new one in without overwriting; if publishing or the post-install check fails it renames the old binary back and reports the original error. The backup path is printed only if that restore failed; otherwise the backup is removed (if it is still in use, as when gjc was running during the install, it is kept as a full-size `.gjc.bak.<id>` file in the install directory and its path is printed; the installer never deletes unknown files by name, so delete that file yourself after closing gjc).
- When `gjc update` holds `.gjc-install.lock` (its lock is a directory), the installer now says so, with the owner process id and whether it is still running, instead of reporting another installer and advising removal of a lock file. It never removes that lock.
