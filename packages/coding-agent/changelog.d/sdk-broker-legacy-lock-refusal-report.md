### Fixed

- A legacy host-unqualified, foreign-host or live-owner `sdk/broker.lock` no longer ends the detached SDK broker with `[Uncaught Exception]` and a crash record. The broker records a typed `startup-lock-refused` exit and `gjc sdk broker run` prints the lock path, refusal code and recovery step to stderr, then exits with status 1 through the public failure output as `broker_unavailable` with the `lock_refused` diagnostic. The lock is never displaced automatically.
- `gjc sdk session` commands now return `broker_unavailable` with a fixed `lock_refused` diagnostic when broker startup refuses an existing lock, instead of a generic `operation_failed`. The next step tells the operator to resolve the lock owner first and carries no runnable command, because any broker-contacting command would only be refused again. The refusal is reported even when the broker could only persist its startup-failure marker. If cleaning up the spawned broker also failed, the result adds a `broker_cleanup_unverified` diagnostic.
