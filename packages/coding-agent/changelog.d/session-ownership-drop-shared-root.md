### Changed

- Every interactive session now writes its session directly, in every `session.ownership.mode` and whether or not gjc could take the session's lock (for example on Windows, after a lock timeout, or when the filesystem has no locks). The shared-publication path that let two terminals write one session as separate branches is no longer used. In `observe` and `off`, star, tree summary (branch with summary), Move Session and `/drop` now work after the first message instead of being refused as "Shared session mutation requires transaction admission".
- Two processes writing the same session no longer branch it. With the default `enforce`, the second one gets the held-session warning, as before. In `observe` or `off`, where gjc could not take the session's lock (Windows, a filesystem without locks, a lock timeout), or with a writer gjc cannot see (an older gjc), there is no warning: the process whose copy of the transcript is out of date stops saving with "Another process changed this session's transcript, so this process stopped saving to it" before its next write. To continue in the stopped terminal, reopen the session with `/resume`, which loads the other process's entries, or fork it from another terminal with `gjc --fork`. If the change is only noticed after this process's entry was written, the write is reported as uncertain rather than refused: the entry is kept in this process, it may already be in the transcript, and this process saves nothing more until the session is reopened.
- This check covers sessions opened from gjc's own session storage (by id, the picker, `/resume`). A session opened by path (`--resume <file>`) or kept in a `--session-dir` has no such check: two processes below `enforce` writing it both append to the file.
