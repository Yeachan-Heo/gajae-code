### Changed

- The Ultragoal ask guard now admits one `ask` once a human-only blocker is verified: the latest `blocker_classified` event is `human_blocked` and a fresh clean pause terminal-critic verdict is bound to it. Previously `ask` stayed blocked regardless of classification, so a run that was allowed to park for the user could not put the human-only request to them as a structured question. Each `human_blocked` classification admits a single answered `ask` carrying exactly one question (reserved in the ledger before the question opens and recorded as a `human_blocked_ask_answered` event once it is answered; a cancelled ask or an `ask.timeout` auto-selection spends nothing; if the answer cannot be recorded it is still returned and the reservation keeps the admission closed, including after a restart), and unlike `goal({"op":"pause"})` no try-harder nudge is spent first. `resolvable`, unverified, rejected, stale, already-spent, and other-session receipts still block `ask`.
