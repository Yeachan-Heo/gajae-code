### Changed

- The Ultragoal ask guard's settlement and reservation infrastructure is in place for human-blocked admission, but admission is currently **disabled at runtime** pending independent provenance verification. The classification and verdict commands are public CLI, and without signed attestation or verified external timestamp from an independent process, the receipt could be self-authored by the active agent to bypass the ask guard. The infrastructure is ready to admit one structured `ask` once human-only blockers can be verified: the latest `blocker_classified` event is `human_blocked` and a fresh clean pause terminal-critic verdict is bound to it. When enabled, each `human_blocked` classification will admit a single answered `ask` carrying exactly one question (reserved in the ledger before the question opens and recorded as a `human_blocked_ask_answered` event once it is answered; a cancelled ask, an `ask.timeout` auto-selection, or a question about the choices spends nothing). The admission is restricted to interactive sessions only; headless answer sources are refused.  
- The reservation recheck holds the plan lock, so a required-goal change cannot slip in between, ensuring receipt freshness is atomic with ask reservation.
