### Fixed

- `transition_claim_timeout` now names why the stale-transition reclaim refused instead of collapsing structurally different situations into one message. A wedged coordinator state claim could previously be a released tombstone from another installation, a tombstone with no installation identity, a live owner, a claim an external process restamped between inspection and capture, or a non-empty claim — all of which needed different operator action and all of which read identically. The error now carries a bounded classifier (for example `(reclaim refused: released_owner_foreign_host)`); it is a fixed enum member and never a path, token, host id, pid, or errno (#5606).
- Same-installation released transition tombstones now hand off immediately instead of waiting through a grace window, so a waiter can reclaim the empty claim without timing out. Windows file-lock publication also retries a bounded sequence of pre-mutation `sharing_violation` results before surfacing the persistence failure (#5606).
