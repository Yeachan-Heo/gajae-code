### Fixed

- `gjc sdk spawn` no longer refuses a timely child host when another process holds the global session index lock until about 8.7 s past the admission deadline. The post-deadline registration recheck now lasts up to 20 s instead of 8 s, and still admits a late host only on its startup commit record. The recheck ends as soon as the outcome is decided: when the host's failure receipt becomes readable or the host process has provably exited, which also ends a wait for the index lock. A completed index read showing that the host's recorded row no longer matches stops further index reads, but the refusal still waits (within the bound) for the receipt or the exit, because a host rolling back unregisters before it writes its receipt; the refusal then reports `child_registration_failed` instead of a timeout. An owner whose process incarnation cannot be read, or that the OS cannot open or query (as on Windows, where such a pid has no process reference), is treated as uncertain and keeps the recheck open; only OS-confirmed absence or a changed incarnation counts as exit, and a row that fails only the read-time liveness check also keeps it open, until the outcome is decided or the 20 s bound passes.
