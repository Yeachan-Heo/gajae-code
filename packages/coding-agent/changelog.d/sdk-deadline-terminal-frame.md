### Fixed

- A prompt that reaches its SDK deadline now delivers the correlated terminal failure frame to ACP and other SDK clients instead of leaving `session/prompt` waiting behind the watchdog (issue #5583).
- A prompt whose deadline expires while its real `agent_end` is in flight now publishes exactly one correlated terminal boundary instead of two, so SDK clients no longer see a duplicate `agent_end` for a turn that reconciled to a single durable outcome.
- A busy session no longer republishes a terminal boundary it already delivered. The single-boundary claim is bounded by capacity, and a publisher parked on its durable writes could have its claim evicted by later turns, so its delayed `agent_end` published a second boundary for an already-terminalized correlation. A correlation with a publisher still able to reach its claim is now never evicted.
- A prompt that reaches its deadline on the notification-bus route — the route a live `--mode acp` session actually uses — no longer supersedes its own expiry. Fencing the run aborts the tool that was still executing, and that tool's completion counted as fresh progress, so the expiry backed off and re-armed forever: no terminal frame ever reached the client and the durable record stayed frozen on its pending claim. Progress caused by the expiry's own abort is now discounted, while progress observed before it still protects a genuinely live prompt.
