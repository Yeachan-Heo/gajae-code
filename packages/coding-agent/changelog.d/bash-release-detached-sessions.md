### Fixed

- A bash tool command that completes normally no longer has the processes it detached into their own session (`setsid()`) SIGKILLed when its shell closes. The most visible case was `git commit` in a repository with many refs: `git gc --auto` spent about a second on `git reflog expire` before detaching, the guardian recorded it in that time, and the detached repack died with `pack-objects died of signal 9`, which git then reported on the next command. Before, whether a detached process survived depended on timing: on macOS it lived only if its parent exited within the guardian's 100 ms scan interval, and on Linux it never did. Now, after a command completes normally, every session it detached into is released and left running. Background jobs that stay in the shell's session (`cmd &`, `nohup cmd &`) are still killed when the shell closes, and a command that is cancelled, times out or dies from a signal still has everything it started killed, including detached sessions.
