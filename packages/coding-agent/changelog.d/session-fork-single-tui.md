### Fixed

- `/fork` works again in an interactive session after messages were sent, including after `--resume` and in sessions with OpenAI Responses or Codex replies. Since v0.21.0 it failed with "Shared session mutation requires transaction admission: prepare branched session" even with no other process open. The fork is built from the session's saved transcript and leaves the source session file untouched. A fork made this way records its source by session id; other fork paths are unchanged.
- When `/fork` still cannot run, it says why (for example, "another gjc process has written to this session" or "this session is too large to fork safely"). In the common case it refuses before it disconnects the agent, settles `/btw` or runs `session_before_branch` hooks. A save that starts in the short window after that check can still refuse later, as before. Sessions whose transcript has been moved to the session-memory sidecar (over 128 MiB, or `sessionMemory.mode: enabled`) still cannot fork from an interactive session; they refuse before any effect.
- `/move` and the `move_session` tool refuse before they start the directory transition when the session cannot be moved.
