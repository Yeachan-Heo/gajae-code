### Fixed

- A TTSR interrupt in a shared session now retries the turn with its reminder instead of leaving the turn aborted with "TTSR recovery was refused because this session entered shared mode". The reminder is saved through the shared session path before the retry changes live history. Only a typed stale or rejected outcome that proves the append did not commit permits retrying with the reminder in memory; an unknown or unclassified persistence failure stops the retry and closes the live session, preventing later prompts from duplicating a possibly committed reminder. The warning includes the attempted entry ID when available. Reconciliation on reopening remains separate. A memory-only retry consumes all of its rules, including carried per-tool claims, in the live manager to prevent a repeatMode once interrupt loop, but writes no durable consumption marker, so the rules remain eligible after reopening.
- A TTSR retry that is aborted or disposed while its reminder is being saved no longer changes live history or claims the rule, and per-tool reminders it carried become eligible again. A newer prompt or interrupt that arrives meanwhile keeps its own TTSR state. A reminder already saved before the cancel stays in the transcript, but its rules are not marked as injected.
