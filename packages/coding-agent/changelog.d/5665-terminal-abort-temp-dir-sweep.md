### Fixed

- The terminal-abort-chain test suite no longer leaks temp agent-state directories. The per-case `finally` already reclaimed the directory on the throwing path, but two paths escaped it: an `afterEach` that exceeds its hook budget is abandoned mid-await so the `finally` never runs, and a writer that outlives teardown can recreate a root the `finally` already removed. Each root is now registered on creation and swept from `afterAll`, which runs in both cases and re-sweeps after a short settle window to catch late writers. A start-of-suite reap also removes roots left by earlier runs, but only ones it can prove are abandoned: each root carries a marker naming the owning pid and host, and a root is removed only when the marker is well-formed, names this host, names a process other than the running one, that process probes as exited (`ESRCH`), and the two-hour age gate has passed. A probe the OS refuses to answer, a missing or malformed marker, and a foreign host all keep the root, so a live shard's directory is never deleted; roots written before the marker existed are consequently never reaped. Measured on macOS, where `os.tmpdir()` is `$TMPDIR` rather than `/tmp`: nine leaked roots per run before, zero after (#5665).
