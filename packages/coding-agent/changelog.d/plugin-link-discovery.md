### Fixed

- `gjc plugin link` now produces a plugin that actually loads. It used to print `✔ Linked …` and exit 0 while `plugin list` reported "No plugins installed", `plugin doctor` reported no manifest, and a fresh session never loaded the plugin's tools, hooks or extensions, because every consumer enumerated only the plugins `package.json` dependencies and a symlink cannot live there (bun copies a `file:` spec and fails to resolve a `link:` one). A linked package is now recorded in the runtime lock file and read through one shared `installedPluginNames`, so the session loader, `plugin list`, `plugin doctor` and the customize doctor agree. `plugin uninstall` of a linked plugin removes the symlink and its record (it previously exited 0 and left the plugin loading) and never touches the linked checkout.
