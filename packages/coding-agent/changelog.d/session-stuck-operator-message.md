### Fixed

- When another process changes a session's transcript, the interactive TUI and startup prompts now show the session's operator message instead of the raw `managed_append_identity_mismatch` code, SDK clients get it instead of an opaque "Control operation failed.", and ACP errors carry it in `data.operatorMessage`. SDK and ACP machine codes, and ACP `details`, are unchanged.
- `/resume`, `/new` and `/fork` work again in a session whose transcript another process changed. Previously the predecessor flush rethrew the identity mismatch, so every way out of the session failed until the process was restarted.
- Once a session is known to be stuck because another process changed its transcript, it refuses new prompts, skills, hidden custom-message turns, `--continue`, steering and follow-ups up front, before admission, hooks, tools or model calls. Extension and custom slash commands that start no turn still run, so status commands and commands that open another session keep working; one that turns into a prompt is refused after its handler runs. The TUI `input` extension hook also still runs first. The message names the recovery: reopen with `/resume` (or `gjc --resume`), or fork with `/fork` (or `gjc --fork`). The first prompt after the other process writes is only refused at its first transcript write, after skill resolution, command dispatch and title invalidation but before any model call. A hidden custom-message turn used to resolve as if it had succeeded, leaving unsaved entries in memory.
- Quitting the TUI from a session whose transcript another process changed no longer crashes with an unhandled `managed_append_identity_mismatch` rejection.
- After any other transcript write failure, those turns are also refused up front with the original error, so a hidden custom-message turn no longer resolves with unsaved entries.
- `/compact` and `/handoff` on a session already known to be stuck are refused before any compaction hook or model call, and their failure text in the TUI and in headless/ACP slash commands shows the operator message.
- Keybinding actions that fail with a session refusal, such as the queue/follow-up shortcut on a stuck session, show the operator message instead of the raw code.
- A context clear on a stuck session is refused before it resets the conversation, and `/move` failures show the operator message.
- A resume rejected during startup, before anything ran in the session, keeps the accurate "this resume did not run" message.
- Turns started without a typed prompt on a stuck session are refused before the system prompt build, recall or `before_agent_start` hooks: the auto-continue prompt, hidden next-turn deliveries, `cancelAndSubmit`, and extension `sendMessage(…, { triggerTurn: true })`. The extension send now reports the failure instead of resolving as a success.
