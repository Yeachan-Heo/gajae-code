### Added

- Generic SDK embedders can use `submitQueuedInput()` and public `queued_input_*` events to correlate identical steering/follow-up submissions with admission, actual consumption, successor promotion, exact owning terminals, and removal/cancellation. Sequential queue policy preserves per-queue FIFO without relying on display entries or internal host hooks (#5429).
- Installed SDK imports and PDF conversion no longer assume a checkout-relative `node_modules` layout. Source and installed SDKs resolve the WASM beside the exact MuPDF loader used by markit; standalone builds embed a package-owned asset generated from that same dependency instance during prepare, prepack, and compilation. Installed-package smoke verifies real PDF conversion independently of the packaged build-time snapshot.
- Queued continuation failures before run admission now restore surviving executable inputs ahead of newer messages, preserving exact submission handles, cancellation, and authorized owned-completion registrations. Irreversible registration settlement and SDK promotion occur only after run acceptance; denied inputs remain filtered rather than resurrected (#5429).
- A steer refused by an idle or unwinding Agent now schedules its follow-up continuation once, including the first queued message. Existing queued work still receives a wakeup, without a duplicate from both the steer caller and follow-up admission.
- Session disposal now cancels revoked observer writes that are still waiting to acquire the coordinator namespace lock. Skipped terminal observations do not enqueue replacement reconciliation, while already-admitted writes and explicit committed-outcome projections retain their cleanup owner until completion. Timeout diagnostics identify the remaining fixed-label write and producer counts without exposing event payloads.

### Changed

- ACP reconciles `uncertain_after_send` from the prompt/skill request itself as well as transport callbacks through one bounded, read-only `turn.result` query. Fresh per-invocation `clientRef` selectors recover lost acknowledgements without replay; unresolved mutations keep their waiter until the attachment is retired rather than admitting another prompt. Unavailable, pending, mismatched, or receipt-less ordinary completion fails explicitly without treating local tool-abort output as a resource cleanup fence (#5401).
- SDK-bus prompt deadlines renew on attributable tool execution, remain bounded by the acceptance-anchored maximum runtime, and reject synthetic pairing-only events. Progress racing durable expiry releases only its superseded deadline claim, preserving real failures, cancellation, and final receipts; expiry diagnostics include correlation and lease state (#5340).
- Runtime sidecars retain sanitized run-correlated failure diagnostics through an empty `agent_end`, without prematurely terminalizing tools or carrying a predecessor's failure into a successor. Branded SDK run capabilities now survive prompt admission; raw caller-supplied tokens cannot forge ownership. Committed bus deadline failures project to the original run's sidecar even after an empty terminal, with explicit unresolved projection diagnostics (#5340, #5401).
- Direct resumed SDK sessions retain descriptor-bound endpoint identity through Broker readiness, replay, and Router publication. Timestamp precision differences are accepted only for the same proven file, while replacement/ownership checks and existing incarnation digests remain unchanged (#5077).
