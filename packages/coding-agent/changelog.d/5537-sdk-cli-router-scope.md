### Fixed

- SDK CLI operations no longer attach to every session host on the machine. `session tail`, `send`, `status`, `inspect`, and the raw control/query globals each address exactly one session id, but opened their Router unscoped, so every invocation dialled the whole fleet. Attaching is not free and is not invisible: each attachment registers as a live client on that host, which resets the host's abandonment window, so periodic single-session tooling kept every unrelated host alive indefinitely — observed as 37 session hosts held open by two polling clients, each host still pinning its language servers and MCP children. Row lookup is the same hazard one layer down: `inspect` and `tail` resolve their session through `session.list`, which the Broker answers over its own client and which therefore needs no session transport at all, yet it attached the whole fleet before the scoped operation ran. The Router scope is now a required argument rather than an omittable one, so a call site cannot silently fall back to fleet-wide: single-session paths pass `[sessionId]`, `search` passes its probed rows, and Broker-answered metadata passes the empty scope.
