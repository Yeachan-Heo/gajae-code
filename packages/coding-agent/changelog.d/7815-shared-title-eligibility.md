### Fixed

- Automatic and manual session titles no longer bar ordinary transcript appends for the rest of the session: title admission is scoped to its publication, while canonical shared appends keep their permanent append and rewrite fences (#7815).
- A title that adopts a transcript already holding state this session never committed keeps whole-transcript rewrite authority barred, so fork, star, and rewrite paths refuse instead of republishing a partial resident graph over the sibling branch. Renaming a transcript this session wrote itself keeps full authority (#7815).
- One-shot publications in a shared session (temporary model change, explicit thinking-level append, discovered-tool selection, mode change, TTSR marker) scope append admission to their own transaction and keep only the whole-transcript rewrite fence, so they no longer bar later appends for the rest of the session (#7815).
- In-turn producers in a shared session publish through the session's admitted path instead of the legacy append, so a refused append no longer aborts the turn and stays operator-visible instead of throwing: extension and hook `appendEntry`/`setLabel` (interactive and subagent executors), tree-navigator labels, todo entries and reminders, goal entries, mode changes, credential pins, session recaps, TTSR injection markers, bash/Python results and deferred command results. An append that is refused or whose durability cannot be confirmed is not reported as persisted (#7815).
- A refused background publication is now operator-visible: the entry is reported with a `session-publication` warning naming the operation and outcome, command results keep their deferred queue slot for retry, and `onPersisted` fires only when the entry is durable. An append whose durable outcome is unknown is reconciled against the transcript first: if the entry is already there it counts as persisted, and if it cannot be proven either way it is reported as unconfirmed and held without resubmission rather than reported as a failure or retried into a duplicate. A retained unconfirmed result is re-read on every later prompt against its original attempted id: once the transcript proves it durable the row is acknowledged and released (without a second append), and only a proven-absent result returns to the ordinary retry queue, so a transient read failure cannot block prompts for the rest of the session (#7815).
- A publication that completes while another publication is being drained no longer waits for the next prompt: the drain owner's settlement now re-checks the queues and publishes any successor batch before prompt preflight finishes, so a command result that arrived mid-drain is in agent state and in order when the run is entered. Failed or unconfirmed rows still stop the drain with their own error and are never retried in a tight loop (#7815).
- A cancelled prompt preflight no longer claims a successor batch: the drain re-reads the turn generation and the admission signal before each batch it strips from a queue — including a bash or Python batch claimed after the previous kind's publication was awaited in the same drain — so a preflight the user already cancelled stops publishing at the claim and does not hold the abort open. Rows it did not claim stay queued for turn finalization or a joining drain, which publishes each of them exactly once (#7815).
- Awaited in-turn producers (custom entries, messages, recaps) publish through the same ordering lane as background producers, so a newer awaited append can no longer commit ahead of an older queued background entry through a free cross-process lease; canonical handlers keep an explicitly admitted path instead of nesting a second lane reservation (#7815).
- A refusal or unconfirmed outcome is described to the operator in stable wording: internal stale-reason codes, attempted entry ids, and raw error text no longer appear in the notice (they stay in the structured log and publication result), while the notice still distinguishes a refused write from one whose durability is unconfirmed. A completion callback that throws after its entry is already durable is reported as a follow-up failure instead of becoming an unhandled rejection, and never causes a second append (#7815).
- A refused or unconfirmed best-effort background publication (extension or hook entry, label, todo or goal entry, TTSR marker) is not retried: a refusal leaves the entry absent from the transcript and the notice is the only recovery signal, while an unconfirmed append may already be in the transcript and is described that way. A publication that throws instead of returning an outcome is reported as unconfirmed, never as a refusal. Only deferred bash/Python/command results keep a queue slot; an unconfirmed result is held without resubmission until reconciliation can decide it (#7815).
- A shared session that hits the managed per-file limit while its only recovery is the barred whole-transcript rewrite now keeps the typed near-limit outcome: the canonical tool result carries `isError`, the structured `nearLimitAppend` metadata, and is delivered to session subscribers instead of degrading into a generic rewrite-required abort. It does not enter legacy todo recovery and does not authorize a rewrite. Because the transcript already sits at its managed per-file cap, nothing further can be appended to it: compaction and `/clear` are otherwise supported through the shared lane, but at the cap each needs an append that cannot grow the transcript, and the rewrite that could reclaim room stays barred, so the retained receipt is described as live-session-only, not durable, with no in-session recovery (#7815).
- A background publication reserves its ordering slot before it waits, so a session switch can no longer send an older queued label, mode change, todo/goal entry, extension entry, or deferred command result into the successor transcript: the origin transcript is captured at reservation and a publication that outlived it is dropped and reported instead of being published (#7815).
- `/clear` in a shared session is admitted through the shared publication path rather than refused: it publishes its parentless context-clear root together with the carried thinking, model, and service-tier entries as one append at the current cursor, so nothing is rewritten and an unseen sibling branch survives; a stale outcome refuses before any live reset and an unconfirmed one fails closed instead of resetting (#7815).
- Picker-starring a non-live predecessor that the picking session published through shared admission (for example after `/new`) now appends an append-only `header_patch` under that predecessor's managed session transaction lease instead of refusing, so a live peer keeps publishing; a predecessor whose header carries no star patch yet still refuses, because that upgrade would be the barred whole-transcript rewrite (#7815).
- Still refused by design in a shared session, unchanged: whole-transcript rewrites, forks, branch switches, session drop/delete/move, staged-selection promotion, in-session `/star`/`/unstar` and live-session picker star writes, and the legacy public append API (#7815).
- The control surfaces split by publication lane on this head instead of all landing on the legacy append: default model selection (durable default model, resume-default, thinking-level, and configured-chain entries in one admitted batch), ACP/SDK session-default selection, temporary model change, model-profile activation, thinking-level changes from a control surface, service tier and fast mode, MCP and discovered-builtin tool selection, credential pins, and mode changes publish through the shared lane. The `setModel` API refuses non-default-role or non-user-selection writes up front, before any live effect. The direct `recordResumeDefaultModel` and `setConfiguredModelChain` helpers, the public synchronous thinking-level append outside the control surface, startup model/chain/thinking overrides, SDK new-session startup appends, and task-executor session init still use the legacy append, so they are refused once the shared session has armed its append bar; none of them is reached by the in-turn producer path. Callers that need durability must use the session's `*ForSession`/`*InBackground` seams (#7815).
- A deferred command result now follows a verified storage relocation of its own transcript instead of being dropped as if the session had switched: publication origin is compared by the manager's transcript lineage, which a verified same-owner relocation preserves while transcript adoption advances it, so a supported relocation neither discards the rest of the spliced batch nor loses its `onPersisted` callbacks (#7815).
- An append whose durability is unknown is reconciled and, when the transcript proves it absent, retried inside the same canonical lane admission as the older deferred result, so a publication already queued behind that result cannot commit newer state ahead of it. A second undecided outcome is retained for the next explicit drain instead of looping (#7815).
