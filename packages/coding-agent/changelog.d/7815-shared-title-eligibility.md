### Fixed

- Automatic and manual session titles no longer bar ordinary transcript appends for the rest of the session: title admission is scoped to its publication, while canonical shared appends keep their permanent append and rewrite fences (#7815).
- A title that adopts a transcript already holding state this session never committed keeps whole-transcript rewrite authority barred, so fork, star, and rewrite paths refuse instead of republishing a partial resident graph over the sibling branch. Renaming a transcript this session wrote itself keeps full authority (#7815).
- One-shot publications in a shared session (temporary model change, explicit thinking-level append, discovered-tool selection, mode change, TTSR marker) scope append admission to their own transaction and keep only the whole-transcript rewrite fence, so they no longer bar later appends for the rest of the session (#7815).
- In-turn producers in a shared session publish through the session's admitted path instead of the legacy append, so a refused append no longer aborts the turn and stays operator-visible instead of throwing: extension and hook `appendEntry`/`setLabel` (interactive and subagent executors), tree-navigator labels, todo entries and reminders, goal entries, mode changes, credential pins, session recaps, TTSR injection markers, bash/Python results and deferred command results. An append that is refused or whose durability cannot be confirmed is not reported as persisted (#7815).
- A refused background publication is now operator-visible: the entry is reported with a `session-publication` warning naming the operation and cause, command results keep their deferred queue slot for retry, and `onPersisted` fires only when the entry is durable. An append whose durable outcome is unknown is reconciled against the transcript first: if the entry is already there it counts as persisted, and if it cannot be proven either way it is reported as unconfirmed and held without resubmission rather than reported as a failure or retried into a duplicate (#7815).
- A refused or unconfirmed best-effort background publication (extension or hook entry, label, todo or goal entry, TTSR marker) is not retried: a refusal leaves the entry absent from the transcript and the notice is the only recovery signal, while an unconfirmed append may already be in the transcript and is described that way. A publication that throws instead of returning an outcome is reported as unconfirmed, never as a refusal. Only deferred bash/Python/command results keep a queue slot, and an unconfirmed result is held without retry (#7815).
- A shared session that hits the managed per-file limit while its only recovery is the barred whole-transcript rewrite now keeps the typed near-limit outcome: the canonical tool result carries `isError`, the structured `nearLimitAppend` metadata, and is delivered to session subscribers instead of degrading into a generic rewrite-required abort. It does not enter legacy todo recovery and does not authorize a rewrite. Because the transcript can no longer grow and both compaction and `/clear` need the shared publication this session refuses, the retained receipt is described as live-session-only, not durable, with no in-session recovery (#7815).
- A background publication reserves its ordering slot before it waits, so a session switch can no longer send an older queued label, mode change, todo/goal entry, extension entry, or deferred command result into the successor transcript: the origin transcript is captured at reservation and a publication that outlived it is dropped and reported instead of being published (#7815).
- Still refused by design in a shared session, unchanged: whole-transcript rewrites, forks, stars, branch switches, session drop/delete/move, staged-selection promotion, `/clear` roots, and the legacy public append API (#7815).
- Also still on the legacy append, and therefore refused once the shared session has armed its append bar: permanent model selection and resume-default recording, the explicit thinking-level append outside the control surface, service tier and fast mode, MCP and discovered-builtin tool selection, the configured model chain, SDK startup appends, and task-executor session init. In-memory state can already be applied by the time one of these refuses, so treat the refusal as visible but not durable; none of them is reached by the in-turn producer path. Callers that need durability must use the session's `*ForSession`/`*InBackground` seams (#7815).
