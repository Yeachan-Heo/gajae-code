### Fixed

- A prompt failure that reaches an ACP client now carries the classification the terminal already computed, instead of collapsing to an untyped `-32603` with `{code: "prompt_failed", details: "Prompt submission failed."}` (issue #5615). The failure's execution `phase`, its bounded origin `category`, and the provider classifier that produced it were derived at settlement and carried on the rejection, then discarded at the single JSON-RPC translation point, so a client watching a mid-session turn die could not tell a transient provider blip from a session that will never answer again without parsing an English message. The JSON-RPC code stays `-32603` (pinned ACP core-v1 conformance expects it for this class) and the redacted message is unchanged; the classification travels in `data`, which additionally exposes a derived `retryability` of `transient`, `terminal`, or `unknown` so a caller does not have to re-implement the category matrix. Only `provider_transport` is transient — the same class the shipped first-turn gate already treats as re-submittable — while a provider rejection, a deadline, and an agent runtime failure are terminal for that turn, and an uncertain attribution stays `unknown` rather than being guessed. `providerCode` is forwarded only when it is a bounded safe token and omitted otherwise, so the redaction contract still holds on this newly exposed field. Retry behaviour is unchanged.
