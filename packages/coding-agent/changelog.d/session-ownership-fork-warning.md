### Changed

- With `session.ownership.mode: enforce` (not the default), resuming a session that another process holds for writing now shows a warning that names the holder, for example "another terminal (pid 4242)", and offers **Fork into a new session** or **Cancel**, instead of refusing. Fork copies the conversation into a new session in this folder, leaving the original untouched, and continues there. This covers `gjc --resume <id or path>` (the warning comes before the "different project" question, which Fork also answers), the bare `gjc --resume` picker (rows held elsewhere are marked, for example `• in terminal`, and Cancel returns to the list), and `/resume` in the TUI (Cancel keeps the current session). Without a terminal, `gjc --resume` still refuses as before. A switch that an extension or an embedding requests onto a held session, and `SessionManager.setSessionFile` onto one, now throw `SessionHeldError` before any event. The printed `gjc --fork` command now repeats a transcript path, quoted for the shell, or adds `--session-dir`, so it finds the same session. `observe` and `off` behave as before.
