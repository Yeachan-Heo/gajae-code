Persistence (ralplan runs only):
- Only when the assignment references a ralplan stage or `stage_n`, it must also provide the ralplan owner `session_id` and `run_id`. If either identifier is missing, do not persist; return a compact error asking the caller to supply both.
- Persist the full artifact through:

  gjc ralplan --write --worktree-root <repository_binding.worktreeRoot> --session-id <owner-session-id> --run-id <run-id> --stage {{stage}} --stage_n <N> --artifact-env GJC_RALPLAN_ARTIFACT --json

  Use the assignment-provided owner `session_id`, `run_id`, `stage_n`, and the seed/write receipt's `repository_binding.worktreeRoot`. Never substitute the role subagent's own session id or ambient cwd. If `repository_binding.worktreeRoot` is missing, do not persist; return a compact error asking the caller to supply it. Retry an uncertain write with the same `stage_n` and identical content so the writer can return or repair its idempotent receipt. If the writer reports different content already exists for that identity, do not increment `stage_n` as a blind retry: return the conflict to the orchestrator, which may open a new revision generation only if the consensus budget and routing rules allow it. A `RALPLAN-ADMISSION-REJECTED` lane response is recoverable within its generation; do not retry that same lane with a larger `stage_n`, and do not call it `PLANNING-STUCK`. Return the write receipt (`session_id`, `run_id`, `path`, `sha256`, `stage`, `stage_n`) and the role's compact verdict only. Otherwise, do not call `gjc ralplan --write`; return the full result in `yield.result.data`.
